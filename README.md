# 🚀 Proyecto Integrador

Este repositorio contiene la documentación y el código fuente del proyecto integrador, organizado bajo metodologías ágiles y control de versiones con Git.

---

## 🌿 1. Gestión del Proyecto con Git y GitHub

### 1.1. Repositorio Público
El proyecto se encuentra en un repositorio público para asegurar la transparencia y trazabilidad de los avances.

### 1.2. Estrategia de Ramas (*Git Flow*)
Se trabaja con un esquema de ramas para separar el código estable de las funciones en desarrollo:
* **`main`**: Rama principal con las versiones finales y estables del proyecto.
* **`develop`**: Rama de integración donde se consolidan las funcionalidades antes de pasar a producción.
* **`feature/<nombre-tarea>`**: Ramas temporales creadas desde `develop` para desarrollar historias de usuario específicas.

### 1.3. Commits Descriptivos
Los mensajes de commit siguen la convención de *Conventional Commits*:
* `feat`: Nueva funcionalidad.
* `fix`: Corrección de errores.
* `docs`: Cambios en la documentación.
* `style` / `refactor`: Formato y mejoras de estructura sin cambiar la lógica.

### 1.4. Integración mediante Pull Requests
Para integrar cualquier cambio en `develop`, se requiere abrir un **Pull Request (PR)** y contar con la revisión de código (*Code Review*) de un integrante del equipo.

---

## 📋 2. Organización Ágil de Tareas

La gestión de las historias de usuario y el seguimiento del proyecto se realiza a través de **GitHub Projects** utilizando un tablero Kanban.

### 2.1. Estados del Tablero
* **Backlog / Todo:** Historias de usuario y requerimientos pendientes.
* **In Progress:** Tareas en desarrollo activo asociadas a una rama `feature/`.
* **In Review:** Funcionalidades finalizadas con Pull Request abierto esperando revisión.
* **Done:** Tareas aprobadas e integradas formalmente en `develop`.

---

## 📈 3. Mecanismos de Control e Informe de IA

### 3.1. Indicadores de Desempeño (KPIs)
1. **Flujo de Historias de Usuario (Sprint Burndown):** Monitoreo semanal de tareas completadas en GitHub Projects.
2. **Revisión Obligatoria de PRs:** El 100% de los cambios integrados a `develop` pasan por revisión de código.
3. **Frecuencia de Commits:** Integraciones pequeñas y continuas en lugar de cambios masivos.

### 3.2. Declaración Transparente del Uso de Inteligencia Artificial
* **Herramientas Utilizadas:** Asistentes de IA Generativa.
* **Campos de Aplicación:**
  1. *Estructuración y Metodología:* Asistencia en la definición del flujo Git y configuración del tablero Kanban.
  2. *Documentación:* Apoyo en el formateo en Markdown para el `README.md` y las Historias de Usuario.
  3. *Sintaxis y Resolución de Errores:* Consultas sobre comandos Git y buenas prácticas.
* **Declaración de Autoría:** Todo el material, código y documentación generado con ayuda de IA fue revisado, probado, adaptado y validado manualmente por el equipo.
